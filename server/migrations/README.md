# 迁移（migrations）

`server/migrations/` 下按 `<三位版本号>_<描述>.sql` 命名（如 `001_members_and_ingredients.sql`），启动时由
`src/db/migrate.ts` 按版本号升序执行，已执行的记录在 `schema_migrations` 表；每个文件一个事务，失败回滚后下次启动重试。
数据资产（折算系数、推荐量、互换表）也写在迁移里：它们与 schema 一样需要「何时入库、来源是什么」的留痕，
而 per-row 的 `source` 列就是那页出处。

- 不要修改已执行过的迁移文件，追加新编号即可（append-only 的 schema 历史）。
- 现有版本：
  - `001_members_and_ingredients` —— 食材字典（规范名 + 别名）与家人画像（大人/小孩、性别、出生年月、忌口、爱吃），
    含本家常用食材与真实家人种子（M1-02 / #14）。
  - `002_recipes_and_meal_slots` —— 家庭菜谱库（成人份生重基准 + 可缩放规则 + 生熟换算锚点 + 治理状态机）、
    食材字典扩充（时令月份 + 隐性忌口「含」指针）、餐槽与留痕事件流（append-only，ADR-0007），
    含家庭常做菜与两道刻意留出的状态样本（M1-03 / #15）。
  - `003_portion_engine` —— 份量引擎的规则资产：成人能量锚点、WS/T 554 分带折算系数
    （系数 = 分带能量 ÷ 同性别成人锚点，两条列都落库）、逐带参考能量（表 1）、
    各人群每天推荐量（成人宝塔 2022 + 学龄前宝塔）、附录 A 生熟/同类互换表（M1-04 / #16）。
    **数据来源逐行写在 source/note 里**：学龄前宝塔数值与 2–3/4–5 档系数是官方图 OCR、
    尚未对照原图复核；成人能量锚点（2250/1800 kcal）来自 DRIs 纸书、书未开放。
    学龄儿童宝塔（6–10/11–13/14–17）**不录**：它的分带与 WS/T 554 的分带对不齐，
    两套并存会让「这个孩子吃多少」出现两个打架的答案（见 003 文件头）。
- 种子数据写在迁移里（而不是启动时补种），这样测试 harness、E2E 的文件库、生产库三条路径拿到的是同一份初值。
- 执行器自身的行为由 `src/db/migrate.test.ts`（临时目录 fixture）覆盖；本目录内容由 `src/db/schema.test.ts` 与
  各 API 集成测试覆盖。
