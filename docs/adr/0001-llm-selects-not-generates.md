# LLM 只从检索池中选菜，不自由生成、不调工具

推荐管线的 LLM（qwen3.8-flash）做的是**选择与搭配**：规则引擎先完成忌口硬过滤（含隐性忌口展开）、时令筛选、去重、按荤/素/汤位检索出候选池，LLM 在单次纯 completion 中从池里配出一餐并给理由，输出仅为菜谱 id。不采用 LLM 自由生成菜名再回库匹配，也不采用 function-calling 工具循环——取数全部前置由后端完成。喜好学习同样零数值权重：点踩走冷藏期规则硬排除，其余反馈以 30 天文本摘要注入 prompt 作软信号。

理由：家庭菜谱库是推荐池唯一来源（票 #3），输出菜谱 id + strict `json_schema` 让幻觉无处发生；「为什么推这道」永远可解释（规则可查 + LLM 理由）；家用量级下快、便宜、可测比 agent 感重要。被否决的备选：LLM 自由生成（幻觉 + 校验重试成本）、工具循环（多轮往返慢且贵）、反馈数值权重模型（需调参、难解释）。M2 的 MCP 化（时令食材等）只改变后端取数的进程边界，不改变本决策——LLM 的调用方形态保持单次 completion。
