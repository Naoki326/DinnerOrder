# 导入来的菜谱：掌勺者在编辑器里确认即信任（部分修正 ADR-0006）

掌勺者**贴一个链接或一段文字**，AI 把它结构化，结果**预填进编辑器**；他校对后点保存，
菜直接以 `status='active'`（家庭库 + 推荐池）入库、`source='oral'`，并记下原始链接。

## 这个决定部分修正 ADR-0006

ADR-0006 说家庭库「只收家里做过、掌勺者确认转正的菜」，外部数据（`howtocook`/`scraped`/`llm`）
必须上桌 + 转正才进家庭库。ADR-0009 已经为**掌勺者手写**开过一条口子。本 ADR 再开一条：
**从链接/文字导入**。

**ADR-0006 对外部数据的门槛一点都不变**：HowToCook / 下厨房批量爬取 / LLM 生成那三条路进来的菜
仍然是草稿，仍然要上桌，仍然要经掌勺者确认才进家庭库。本 ADR 与 ADR-0009 一样是**部分修正**：
门槛防的是「未经家人验证的外部数据」，不是「掌勺者当场确认过的一份菜谱」。

## 信任的根：不是来源干净，是「有人逐项看过」

这一条与 ADR-0009 的信任根**不同**，值得说清，否则后来者会以为代码放松了标准：

* ADR-0009 的根是**身份**——「他既是录入者，也是那个要确认它的人」；
* 本 ADR 的根是**形状**——导入这条路上**根本没有「直接入库」的函数**。
  `POST /recipes/import` 的产出是一份**预览**（`RecipeImportPreview`），它唯一的去处是
  `RecipeEditor` 的草稿；落库只能走既有的 `POST /recipes`，而那条路要求一份完整的
  表单输入（含逐项 > 0 的克数）。「LLM 产出的东西没人看过就进库」在类型上就不可能发生。

于是不必在信任判定里加新条件（「哪些来源算可信」），也就不会出现「同一个 `source` 值
有时可信有时不可信」这种读不懂的状态。**生产环境的 `source` 值域一个都没加**
（迁移 015 加的是 `source_ref` 这个**出处**列，不是第五个信任档，理由见那个文件）。

## 理由

**没做过的菜进推荐池，这件事 ADR-0009 已经接受了。** 家里有一道从视频学来的新菜想下周做，
和家里有一道自己写着玩的新菜想下周做，是同一件事。真正的区别只在「菜谱内容从哪来」——
而那是 `source_ref` 要回答的（可回溯），不是「能不能进推荐池」要回答的。

**「待重标」的语义没有被绕过。** 库里 `adult_grams = 0` 的唯一含义是「模糊份量待 LLM 重标」。
导入预览**不往库里写 0**：模型没给克数的项在预览里是 0，而既有编辑器的校验会**拦住保存**
（红框 + 不给保存）——他必须为那一项填一个数。想把外部素材**批量**灌进草稿池的，仍然走
`importDrafts` 那条路（那是 ADR-0006 的原义）。

## 三条判据

* **难逆转**：又放宽了一类数据进推荐池的条件。放宽之后再收紧，等于把掌勺者从链接导进来的菜
  赶出推荐池。
* **无上下文会困惑**：未来读到「一条小红书链接导进来的菜，没做过就在推荐池里」会以为代码坏了
  ——这句解释必须写在这里。
* **真实取舍**：严格守门槛（导入的菜先进草稿、上桌转正）vs 信任当场校对（他正看着那份清单）。
  选了后者，代价是「导入质量」依赖他看得仔细；换来的是导入这一步不是白干。

## 被否决的备选

* **导入的菜落成草稿（走 ADR-0006 原义）**：最保守，但会让这个功能在真实使用里几乎没用——
  家里从链接学一道菜，本意就是「这周做它」，而不是「先存进一个我不看的池子、等哪天做过再转正」。
* **给 `source` 加第五个值 `imported` / `link`**：看起来更"如实"，但会**同名不同义**——
  `source` 现在回答「信任档」，加了之后同一个字段里混着「信任档」与「出处」两种语义，
  而 ADR-0006 的门槛判定读的正是这个字段。要加就得重建 `recipes` 放宽 CHECK，
  而 SQLite 在 `foreign_keys=ON` 下做不到（子表引用着它；事务内关 FK 是无效的）——
  一次代价不小、收益只是"枚举好看"的重建。
* **导入时顺手把克数写进库（绕过编辑器）**：那是把「AI 估的量」直接当成人份基准，
  ADR-0004 的「数值路径不进 LLM」就真被绕过了。本 ADR 的底线就是「必有人看过」。

## 边界（本决定不管什么）

* **`source` 是什么就还是什么**：导入来的菜是 `'oral'`（掌勺者确认过的手艺，与 ADR-0009 同档）。
  它**不是** `'scraped'`——那意味着「未经确认的外部素材」。原始链接记在 `source_ref`。
* **转正这条路一点没动**：外部池的菜仍然要上桌 + 转正（ADR-0006、ADR-0009 都没被本 ADR 碰）。
* **取正文的能力边界如实告知**：取正文是**站点无关的尽力而为**（链接来自哪里不可预知——
  小红书、下厨房、知乎、博客、自建站…），失败时报 `fetch_failed` 并提示「改用贴文字」，
  不在解析里堆越来越脆的启发式。三档阶梯与两条硬纪律见
  `server/src/import/extract.ts` 的文件头：
  **① JSON-LD `Recipe`**（schema.org 标准，最通用，菜谱站与很多媒体都嵌）
  **② 站点适配器**（只有结构特殊到通用档读不出来的才写，目前只有小红书——视频做法在字幕里）
  **③ 通用正文**（**带证据闸门**：正文太薄、或找不出步骤/份量信号就报错）。
  两条硬纪律：**抓不到就诚实报错**（很多站点要登录/人机验证，实测下厨房的拦截是**摇摆的**，
  同一链接一次成功一次被挡——这不是缺陷而是现实），以及**绝不静默替换内容**
  （通用档从整页抽文字会命中推荐流的其他菜谱，实测拿到过「想要 A 菜、得到 B 菜」，
  所以证据不够时宁可报错）。
