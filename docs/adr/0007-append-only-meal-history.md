# 菜单历史是 append-only 留痕事件流

菜单的一切变化——预定（接受整餐推荐）、换单道、换一整套、取消——各记一条不可变事件，按序追加（append-only）；当前菜单状态由事件流折叠得出。「吃过什么、换过什么」的全部历史查询——同菜去重窗口、冷藏期、近 30 天反馈摘要、近 7 天已吃列表——直接查事件流，不另建汇总表。事件同时携带 LLM 调用元数据（模型名、prompt 模板版本、耗时、是否降级），模板进代码库 git 管版本。

理由：去重与喜好机制天然依赖历史，而历史的唯一可靠形态就是发生过的事实序列；append-only 让「为什么推这道 / 为什么没推」永远可回溯，且与每日 SQLite 热备天然兼容（追加不重写，增量备份不膨胀）。被否决的备选：可变状态表 + 独立历史表（CRUD 直觉，但两处一致性易漂移、历史表常在「优化」中被砍）；只存当前菜单不留历史（去重/冷藏/摘要全部失去数据源，等于砍掉「历史积累喜好」这条产品闭环）。
